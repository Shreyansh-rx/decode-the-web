College Portal Investigation

A college portal contains complex structural issues and hidden DOM clues. Use your DevTools skills to investigate and fix the underlying problems.

📋 Problem Statement

You've been given a college portal webpage that appears normal at first glance, but contains deep structural issues hidden within the DOM. The page has dynamically injected elements, misleading class names, hidden attributes, and structurally inconsistent markup that affects how the browser interprets the content.

This challenge tests your ability to use browser Developer Tools to inspect, investigate, and understand complex HTML structures — not just surface-level bugs.

✅ Requirements

  • Open the provided HTML file and inspect the DOM using browser DevTools (Elements panel).
  • Identify structural inconsistencies — elements that are present in the DOM but not visible, or visible but incorrectly placed.
  • Investigate dynamically generated elements (check for JavaScript that modifies the DOM after page load).
  • Find hidden data attributes (data-*) that contain clues about what's broken.
  • Trace the root cause of rendering issues — misleading CSS classes, incorrect ARIA attributes, or invisible elements affecting layout.
  • Fix the underlying HTML issues to make the portal render correctly and accessibly.

🎯 Expected Behaviour

When correctly fixed, the college portal should:

  • Display a complete navigation menu with all links visible and functional.
  • Show student dashboard cards with correct data (not hidden or overlapping).
  • Render the course schedule table with all rows visible.
  • Have all announcements section items displayed in chronological order.
  • Pass accessibility checks — correct ARIA roles, proper heading hierarchy, and valid semantic structure.

🔍 Investigation Hints

💡 Where to Look

Use the browser Elements panel to inspect the full DOM tree. Some elements may have display: none or visibility: hidden applied via inline styles or misleading class names. Check data- attributes for encoded clues. Look at the page source vs. the live DOM to spot dynamically injected differences.

💻 Starter Code Preview

The challenge file is more complex than what's shown here. Below is just a structural overview:

portal.html 
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>UniPortal - Student Dashboard</title>
  <style>
    /* Some CSS is intentionally misleading */
    .visible { display: none !important; }
    .hidden-section { /* actually visible */ }
    [data-status="active"] { opacity: 0; }
  </style>
</head>
<body>
  <header>
    <nav aria-label="Main Navigation">
      <ul>
        <li><a href="#">Dashboard</a></li>
        <li class="visible"><a href="#">Courses</a></li>
        <li><a href="#" style="display:none">Grades</a></li>
        <li data-clue="check-aria">
          <a href="#" aria-hidden="true">Schedule</a>
        </li>
      </ul>
    </nav>
  </header>

  <main>
    <!-- Dashboard cards with hidden data -->
    <section data-section="dashboard" data-status="active">
      <h2>Student Overview</h2>
      <!-- Cards are here but some are invisible... -->
    </section>
    
    <!-- More sections with deeper issues... -->
  </main>

  <script>
    // DOM manipulation happens here after load
    document.addEventListener('DOMContentLoaded', () => {
      // Dynamically modifies elements...
    });
  </script>
</body>
</html>

Download the starter file and open it in your browser.

Use DevTools (Elements, Console, Computed Styles) to investigate the DOM thoroughly.

Fix all the HTML, CSS-class, and attribute issues you discover.

Verify the portal renders completely and correctly, then submit before the deadline.
