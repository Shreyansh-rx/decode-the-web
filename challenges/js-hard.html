The Broken Dashboard

An interactive analytics dashboard suffers from erratic asynchronous updates, severe race conditions, duplicate event listeners, and memory leaks. Debug the runtime engine.

📋 Problem Statement

You are tasked with fixing a critical, real-time analytics dashboard application. While the user interface loads, clicking filters and switching tabs triggers bizarre and intermittent bugs:

  • Asynchronous Race Conditions: When rapidly clicking between "Today", "7 Days", and "30 Days", an earlier slow network request resolves after a fast one, displaying stale, outdated metrics.
  • Duplicate Event Listeners: Each time the metrics table is re-rendered, event listeners are attached repeatedly to action buttons without debouncing or cleanup, firing 10+ duplicate alerts and API requests on a single click.
  • Unsynchronized Promise Rejections: A failed simulated endpoint crashes the entire event loop because error handling or fallback states are missing.
  • Incorrect Data Transform: Summary statistics calculate averages incorrectly due to mismatched keys and mutation of the original cached data array.

✅ Requirements

  • Eliminate Race Conditions: Implement a request cancellation token or track an incremental request ID (or abort controller) so only the latest requested dataset is rendered.
  • Fix Event Listener Duplication: Use proper event delegation on a stable parent container, or cleanly unbind previous listeners before re-attaching.
  • Robust Asynchronous Handling: Wrap asynchronous calls in proper try...catch blocks and display a non-blocking error/loading state.
  • Immutable Data Transformations: Ensure filtering and calculating totals do not destructively mutate the primary global dataset.
  • Accurate Metric Calculations: Fix the metric summation formulas so total revenue, active users, and conversion percentages reflect the active time range.

🎯 Expected Behaviour

  • Rapidly clicking different date filters always displays the data corresponding to the last clicked tab.
  • Action buttons (e.g., "Export Row", "Refresh") fire exactly once per click.
  • Simulated network latency or timeouts do not freeze the UI or log unhandled Promise rejections.
  • The summary metrics match the rendered table rows precisely.
  • Memory usage remains stable during frequent tab switches.

🔍 DevTools Investigation Tips

💡 Inspect Event Listeners Panel

In Chrome DevTools, inspect any button inside the dashboard table and look at the Event Listeners tab on the right panel. Check if multiple listeners of type click are stacked on the same element.

💡 Network Throttling & Console Breakpoints

Simulate slow 3G or variable network latency in the DevTools Network tab to expose the async race condition immediately. Use conditional breakpoints inside the async resolver function.

let activeTimeframe = 'today';
let cachedData = [];

// BUG 1: Severe Race Condition
// When users click quickly, slow requests resolve after quick ones!
function fetchDashboardData(timeframe) {
  showLoader(true);
  
  // Simulated variable API latency (50ms - 1500ms)
  const simulatedDelay = timeframe === '30days' ? 1200 : 200;
  
  setTimeout(() => {
    const data = generateMockData(timeframe);
    // BUG: No check whether 'timeframe' is still the currently selected one!
    cachedData = data;
    renderMetrics(cachedData);
    renderTable(cachedData);
    showLoader(false);
  }, simulatedDelay);
}

// BUG 2: Duplicate Event Listeners added on every re-render!
function renderTable(items) {
  const tbody = document.getElementById('table-body');
  tbody.innerHTML = '';
  
  items.forEach(item => {
    const tr = document.createElement('tr');
    tr.innerHTML = \`
      <td>\${item.name}</td>
      <td>$\${item.revenue}</td>
      <td><button class="btn-action" data-id="\${item.id}">Action</button></td>
    \`;
    tbody.appendChild(tr);
  });

  // BUG: Adding document-wide or querySelectorAll listener on EVERY render!
  document.querySelectorAll('.btn-action').forEach(btn => {
    btn.addEventListener('click', handleActionClick); // Multiplies exponentially!
  });
}

function handleActionClick(e) {
  console.log("Action triggered for:", e.target.dataset.id);
  // Fires 4x, 8x, 16x as you switch tabs!
}
