Shopping Cart Repair

An e-commerce shopping cart module contains state synchronization, math calculation, and DOM removal bugs. Repair the JavaScript cart logic.

📋 Problem Statement

An e-commerce web application has an interactive shopping cart drawer. Customers and testing teams have reported critical runtime bugs:

  • When increasing item quantities, the price does not multiply properly or produces NaN.
  • When decreasing quantity to zero, items remain in the cart with negative quantities.
  • Clicking the "Remove" button removes the HTML item from the screen, but the total price does not update.
  • Floating-point inaccuracies produce weird prices like $59.99000000000001 instead of $59.99.
  • When all items are deleted, the cart shows empty rows instead of the "Your cart is empty" placeholder, and the checkout button remains clickable.

Your goal is to refactor and debug the cart logic so state management, calculations, and DOM mutations are completely synchronized.

✅ Requirements

  • Fix the updateQuantity(itemId, change) function to adjust quantities correctly and prevent negative or zero quantities unless removing.
  • Implement accurate price calculations: recalculate item row subtotals (price * quantity) and total order sum.
  • Format all rendered currency values to strictly 2 decimal places using toFixed(2).
  • Fix the removeItem(itemId) function to update the underlying items array and recalculate totals accordingly.
  • Properly handle the empty cart state: show the empty banner message and disable the Checkout button when the cart contains 0 items.
  • Ensure DOM events delegate properly and do not throw uncaught errors when buttons are clicked rapidly.

🎯 Expected Behaviour

  • Changing quantity updates both the item row price and the cart total synchronously.
  • Removing an item subtracts its value from the grand total immediately.
  • All displayed monetary figures are formatted as $XX.XX.
  • Empty cart displays a clear "Your cart is empty" notification and disables "Proceed to Checkout".
  • No errors logged in developer console.
