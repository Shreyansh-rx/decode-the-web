Rules & Scoring

Everything you need to know before the competition starts. Read carefully.

Guidelines

Competition Rules

Follow these rules to ensure fair play and a smooth competition experience.

🎯

Format

The competition consists of 9 challenges distributed across HTML, CSS, and JavaScript. You are free to tackle challenges in any sequence you prefer.

👤

Individual Work

Participants must work individually. Collaboration with other participants during the competition is not permitted.

🛠️

Allowed Tools

You may use VS Code (or any text editor) and browser Developer Tools (Inspect Element, Console, Network, and Computed Styles).

✨

Clean Code & Structure

Write clean, well-formatted code. Proper indentation, semantic tags, and descriptive variable names will be considered during manual review.

🌐

Browser Testing

Always test your solutions directly in a modern browser. Check for console errors, responsive layouts, and visual parity with the expected design preview.

📋

No Copying

Copying another participant's work is strictly prohibited. Each submission must be your own authentic work. Plagiarism will result in disqualification.

📤

Submission Procedure

Package your corrected source files as instructed and submit your final work to the organizers before the announced submission cutoff.

📝

Manual Evaluation

All submissions will be manually evaluated by the organizers. There is no automated testing or grading system.

⚖️

Final Decision

The organizers' decisions regarding scoring and results are final. No appeals or disputes will be entertained.

💡 Pro Tip for Hard Challenges

Hard challenges (worth 20 points each) are designed to test deep debugging skills. Make full use of browser DevTools: inspect DOM nodes, check CSS specificity in the Computed styles panel, and use breakpoints to trace runtime logic.
